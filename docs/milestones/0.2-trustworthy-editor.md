# Milestone 0.2 — Trustworthy editor

## Outcome

A writer can use the existing folder-based editor without reasonably fearing that ordinary navigation, save failure, or an interrupted application will silently discard work.

## Scope

### 0.2.1 — Safety baseline

- Establish frontend test infrastructure and record baseline checks.
- Introduce an explicit save-state model with focused unit tests.
- Extract logic from the page only where it improves safety or testability.

Complete when the existing workflow remains functional, save-state transitions are testable, and frontend checks pass.

### 0.2.2 — Autosave

- Save after a short idle interval without interrupting typing.
- Expose understandable dirty, saving, saved, and failed states.
- Prevent an older asynchronous write from incorrectly marking newer content as saved.
- Retain dirty state and a recoverable error when a write fails.
- Keep `Command/Ctrl+S` as an immediate save action.

Complete when autosave behavior and race handling are covered by tests and verified in the desktop app.

### 0.2.3 — Safe navigation

- Flush or resolve pending saves before changing the active file or folder.
- Handle window-close behavior when content cannot be safely saved.
- Avoid overwriting a newly selected file with a late save from the previous file.
- Provide a clear choice only when automatic safe continuation is impossible.

Complete when file switching, folder switching, and closing cannot silently discard acknowledged edits.

### 0.2.4 — Recovery

- Keep a local recovery copy while content is dirty or a save is in flight.
- Detect a newer recovery copy on launch or file reopen.
- Let the writer restore, compare sufficiently to decide, or dismiss the recovery copy.
- Remove stale recovery data only after confirmed persistence or explicit dismissal.
- Document where recovery data lives and ensure it never leaves the machine.

Complete when a forced interruption can be simulated and the latest recoverable text is offered on restart.

### 0.2.5 — File-tree usability

- Sort directories before files and use stable locale-aware names.
- Preserve useful expansion and selection state on refresh.
- Create a file in the selected directory, not only the project root.
- Prevent accidental overwrite and handle invalid names explicitly.
- Refresh the smallest useful portion of the tree after a change.

Complete when nested folders feel predictable with keyboard and pointer input.

### 0.2.6 — Window and permissions

- Add accessible minimize and close controls to the frameless window.
- Preserve drag behavior without making controls draggable.
- Review macOS keyboard/window conventions.
- Replace broad static filesystem access with the narrowest reliable selected-folder scope supported by Tauri.
- Remove unused template commands and plugins when safe.

Complete when native window behavior works and the permission model is documented and tested.

### 0.2.7 — Milestone QA

- Exercise unreadable, deleted, renamed, and externally modified files.
- Exercise write denial, folder removal, rapid navigation, and rapid typing.
- Check keyboard access, focus visibility, error announcements, and basic contrast.
- Run frontend and Rust validation plus a production build.
- Update the README's current features and limitations.

## Out of scope

- Daily word tracking
- World-project formats and templates
- Wiki links and project-wide indexing
- Scene/chapter organization
- Cloud backup or sync

## Milestone exit criteria

- No known ordinary interaction silently loses unsaved text.
- Recovery behavior is documented and manually demonstrated.
- Broad filesystem access has been removed or a documented Tauri limitation and mitigation is recorded.
- Automated checks and production builds pass.
- `ROADMAP.md` marks 0.2 complete and `docs/CURRENT.md` activates 0.3.
