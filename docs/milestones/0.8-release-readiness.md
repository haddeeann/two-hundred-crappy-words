# Milestone 0.8 — Release readiness

Status: **ACTIVE** as of 2026-10-08.

## Outcome

Another writer can install, understand, evaluate, back up, and safely remove the application.

## Planned slices

### Accessibility and usability

- Keep native macOS Zoom and full-screen semantics rather than imitating traffic-light controls; verify that Zoom remains minimizable and document that true full screen is an operating-system Space.
- Hide dot-prefixed operating-system and tool metadata from the project tree by default, with a keyboard-accessible app-local preference to reveal it.
- Complete keyboard-only workflows and visible focus states. *(Structured audit complete in 0.8.2.)*
- Verify screen-reader names, announcements, landmarks, and ordering. *(Structured audit complete in 0.8.2.)*
- Support zoom, text scaling, reduced motion, and sufficient contrast. *(Complete in 0.8.2; performance remains a separate slice.)*
- Test empty, loading, success, and error states with representative users or structured review.

### Reliability and performance

- Build representative small, medium, and large project fixtures. *(Portable restore fixture complete in 0.8.3; performance-scale fixtures continue in 0.8.4.)*
- Set and measure budgets for launch, file opening, typing, autosave, search, and indexing. *(First local baseline complete in 0.8.4; file opening remains covered by launch/manual QA until privacy-safe local diagnostics exist.)*
- Exercise backup, restore, recovery, and every supported format migration. *(Complete for current version-one formats in 0.8.3; no automatic format migration is currently supported.)*
- Document known limits rather than hiding them.

### Product understanding

- Add concise onboarding that gets a writer to the editor quickly. *(Complete in 0.8.5a.)*
- Include an optional sample science-fiction world. *(Complete in 0.8.5b.)*
- Add contextual help for goals, projects, links, structure, and continuity. *(Complete in 0.8.5a.)*
- Maintain user documentation and a clear project-data reference. *(Current README and data/format references updated through 0.8.5b.)*

### Distribution

- Finalize product naming, identifiers, icons, and versioning.
- Establish macOS signing/notarization and an update strategy before public distribution.
- Define Windows/Linux support based on tested capability rather than Tauri's theoretical targets.
- Produce a reproducible release checklist and rollback plan.

### Privacy and feedback

- Publish an accurate privacy statement and data-location guide.
- Keep telemetry and crash upload disabled unless separately approved and transparently designed.
- Provide a user-controlled way to export diagnostic information without manuscript content.
- Define beta feedback and issue-reporting channels before inviting testers.

## Decision gates

- Approve final visual identity and product language.
- Approve signing/distribution accounts and any associated cost.
- Approve any networked update, crash-reporting, or feedback service.

## Milestone exit criteria

- A clean Mac can install, launch, use, back up, and uninstall the app from written instructions.
- Accessibility and performance reviews meet documented targets.
- Privacy and data-location behavior match the implementation.
- A release candidate passes the complete checklist without relying on developer-only state.
