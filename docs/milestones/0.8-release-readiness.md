# Milestone 0.8 — Release readiness

## Outcome

Another writer can install, understand, evaluate, back up, and safely remove the application.

## Planned slices

### Accessibility and usability

- Complete keyboard-only workflows and visible focus states.
- Verify screen-reader names, announcements, landmarks, and ordering.
- Support zoom, text scaling, reduced motion, and sufficient contrast.
- Test empty, loading, success, and error states with representative users or structured review.

### Reliability and performance

- Build representative small, medium, and large project fixtures.
- Set and measure budgets for launch, file opening, typing, autosave, search, and indexing.
- Exercise backup, restore, recovery, and every supported format migration.
- Document known limits rather than hiding them.

### Product understanding

- Add concise onboarding that gets a writer to the editor quickly.
- Include an optional sample science-fiction world.
- Add contextual help for goals, projects, links, structure, and continuity.
- Maintain user documentation and a clear project-data reference.

### Distribution

- Finalize product naming, identifiers, icons, and versioning.
- Establish macOS signing/notarization and an update strategy before public distribution.
- Define Windows/Linux support based on tested capability rather than Tauri's theoretical targets.
- Produce a reproducible release checklist and rollback plan.

### Privacy and feedback

- Publish an accurate privacy statement and data-location guide.
- Keep telemetry and crash upload disabled unless separately approved and transparently designed.
- Provide a user-controlled way to export diagnostic information without manuscript content.
- Define beta feedback and issue-reporting channels before inviting testers.

## Decision gates

- Approve final visual identity and product language.
- Approve signing/distribution accounts and any associated cost.
- Approve any networked update, crash-reporting, or feedback service.

## Milestone exit criteria

- A clean Mac can install, launch, use, back up, and uninstall the app from written instructions.
- Accessibility and performance reviews meet documented targets.
- Privacy and data-location behavior match the implementation.
- A release candidate passes the complete checklist without relying on developer-only state.
