# Milestone 0.4 — World projects

## Outcome

A writer can create or adopt a portable project that organizes a manuscript and science-fiction world without surrendering ownership of ordinary files.

## Planned slices

### Project model

- Define a small, versioned, human-readable project manifest.
- Continue supporting an unmodified ordinary folder.
- Detect, explain, and safely migrate future manifest versions.
- Keep machine-specific state outside portable project metadata where appropriate.

### Project creation

- Create a named project through a native folder flow.
- Offer a restrained default structure: Manuscript, Characters, Locations, Factions, Species, Technology, Timeline, Research, and Inbox.
- Let an experienced writer omit or change suggested folders.
- Never overwrite existing material during adoption.

### Markdown and templates

- Treat Markdown as editable text without requiring rich preview.
- Define documented frontmatter conventions only for structured features that need them.
- Provide optional templates for character, location, faction, species, technology, spacecraft, event, scene, and chapter notes.
- Make prompts easy to ignore or delete.

### Project navigation

- Create items in the selected folder from an appropriate template.
- Remember open project, selected file, expansion, and useful editor state.
- Add recent projects and clear missing-project recovery.
- Document backup and project portability.

## Decision gate

Review the proposed on-disk manifest and frontmatter format before treating it as stable user data.

## Milestone exit criteria

- A new world project can be created, closed, moved, and reopened.
- An existing folder can be adopted without content changes.
- Project files remain understandable in a general text editor.
- Format and backup documentation are complete.
